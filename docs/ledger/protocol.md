# Experiment and statistics protocol

Binding for every E-job and for any code job that reports a number. Changing a rule here
needs a team decision recorded in the PR description.

## 1. Splits

- **Dev:** the 200 questions in `results/questions-200.jsonl`. All tuning, thresholds,
  calibration and design choices use dev only.
- **Test:** the pre-registered set from J05, disjoint from dev by `(dataset, split, id)`.
  It is run **once per frozen configuration** (E06). Never look at test results and then
  change a configuration.
- **Train (labels for S3b/Q5/J23):** benchmark train splits, disjoint from dev and test.
  StrategyQA only ships a train split: if dev already uses StrategyQA/train, train labels
  must come from other StrategyQA/train IDs, and the overlap check must prove it.

## 2. Pairing and conditions

- Every comparison is paired: same questions, same retrieval cache (J04), same answer
  extractor, same commit, same environment.
- Interleave or randomise run order across arms, so drift in caching or the GPU does not
  favour one arm.
- **Baseline arm = the baseline rerun by E00 with the current runner,** never the
  historical `results/` numbers.
- Record the variant JSON, commit, environment and command in `run-manifest.json`.

## 3. A/A noise floor

Before comparing arms that should give identical answers, run the same configuration
twice on 50 dev questions. Record:
- the EM flip count;
- the output-hash mismatch count;
- the passage-ID mismatch count.

Greedy decoding is not bit-identical under batching or prefix caching. An
answer-preserving change passes if its mismatches do not exceed the A/A floor.

## 4. Tests to use

| Question | Test |
| --- | --- |
| Accuracy difference (EM, acc) | Exact McNemar: pooled primary; per dataset with Holm–Bonferroni |
| F1 or other continuous scores | Paired bootstrap, 10,000 resamples, 95% CI; seeded |
| "No worse than" (speed changes, budgets) | TOST non-inferiority: ±0.5 pp for answer-preserving changes, ±1 pp for method changes |
| Latency | Per-question paired seconds; median and p90 with bootstrap CIs; Wilcoxon signed-rank |
| Throughput | Questions/hour over three repeats; median and IQR |
| Calibration (gates, routers) | ECE, reliability diagram, AUROC/AUPRC, leave-one-dataset-out validation |
| Coverage (conformal) | Empirical coverage with a Clopper–Pearson interval |

**Sample size:** `n ≈ [z_{α/2}√ψ + z_β√(ψ − δ²)]² / δ²`, where ψ is the discordant
fraction and δ the effect. At ψ ≈ 0.19 and 80% power, δ = 5 pp needs n ≈ 590. Report
the minimum detectable effect with every result.

## 5. Reporting

Report per arm:
- EM, F1, acc, Recall@k;
- calls and tokens per question;
- median and p90 s/question, and questions/hour;
- startup time (separately);
- peak VRAM;
- the A/A floor.

Report null and negative results with the same detail. Figures use **Matplotlib** (slide
21), generated by a committed script, never by hand.

## 6. Promoting evidence

E-jobs write raw output to `new-runs/` (ignored). They commit only compact evidence:

```
experiments/<JOB-ID>/
  README.md        what was run, why, exact command, commit, variant files, environment, outcome
  summary.json     the numbers reported in the ledger
  figures/*.png    Matplotlib, from a committed script
  tables/*.csv     small per-question or per-arm tables (each file <= 1 MB)
  SHA256SUMS       checksums of everything above
```

- `results/` stays frozen.
- A ledger fact becomes **[M]** only by linking its `experiments/<JOB-ID>/summary.json`
  entry.
- Raw logs too large to commit stay in the local archive. The README says where, and
  gives their checksums.

## 7. Stage gates

| Stage | Jobs | Pass condition |
| --- | --- | --- |
| 0 | J00–J05, E00 | CI enforces limits and frozen paths; baseline rerun matches the recorded baseline within the A/A floor; stage-timing figure exists; test set pre-registered |
| 1 | J06, J07, J09, E01 | Answer-preserving changes within the A/A floor; paired latency CI excludes 0 |
| 2 | J08, J10–J14, E02a, E02b | Each method change is EM non-inferior (TOST 1 pp) or significantly better; calls and latency reported |
| 3 | J15–J19, E03, E04 | Throughput ≥ 1.2× with no state leakage; Q1/Q4 paired gains on pre-specified subsets |
| 4 | J20–J23, E05 | Router beats random routing at equal DRAG share on the EM-vs-seconds Pareto curve; conformal coverage within 2 pp |
| 5 | E06 | Frozen configurations evaluated once on the test set, per this protocol |

A job does not have to wait for a stage to finish unless its dependencies (jobs.md)
require it. The gates decide which configurations go forward to E06.
